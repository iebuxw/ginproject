# 内网 HTTPS 支持实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为内网项目启用 HTTPS：nginx 监听 443（宿主机 8443），HTTP 8080 自动 301 跳转到 HTTPS，证书为宿主机自签。

**Architecture:** 证书由宿主机 `certs/` 目录（gitignore）存放，通过 docker-compose 只读挂载进 nginx 容器；nginx.conf 增加 443 ssl server 块（TLS 终止 + HTTP/2），原 80 server 块改为 301 跳转。前端 SPA、`/api/` 代理、WebSocket（升级为 wss）配置原样保留。

**Tech Stack:** nginx:1.24-alpine、openssl、docker compose

**前置条件：** 设计文档 `docs/superpowers/specs/2026-08-27-https-design.md` 已提交。任务 1 需要宿主机有 openssl（Git Bash 自带），若无则用 `docker run --rm -v "$PWD/certs:/certs" alpine/openssl ...` 替代（步骤中有说明）。

### Task 1: 自签证书生成脚本 + gitignore

**Files:**
- Create: `gen-cert.sh`
- Modify: `.gitignore`

- [ ] **Step 1: 创建 gen-cert.sh**

写入以下内容（注意 LF 换行）：

```bash
#!/bin/sh
CERT_DIR="$(dirname "$0")/certs"
mkdir -p "$CERT_DIR"
if [ -f "$CERT_DIR/server.crt" ] && [ -f "$CERT_DIR/server.key" ]; then
    echo "证书已存在，跳过生成"
    exit 0
fi
openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout "$CERT_DIR/server.key" -out "$CERT_DIR/server.crt" \
  -subj "/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
echo "证书已生成: $CERT_DIR/server.crt"
```

- [ ] **Step 2: 运行脚本生成证书**

Run: `sh gen-cert.sh`
Expected: 输出 `证书已生成: certs/server.crt`，且 `ls certs/` 出现 `server.crt` 与 `server.key`

若报 `openssl: command not found`，改用容器生成：

```bash
mkdir -p certs && docker run --rm -v "$PWD/certs:/certs" alpine/openssl req -x509 -nodes -days 3650 -newkey rsa:2048 -keyout /certs/server.key -out /certs/server.crt -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
```

- [ ] **Step 3: 验证证书 SAN 与有效期**

Run: `openssl x509 -in certs/server.crt -noout -text | grep -A1 "Subject Alternative Name" && openssl x509 -in certs/server.crt -noout -dates`
Expected: SAN 含 `DNS:localhost, IP Address:127.0.0.1`；`notAfter` 为 2036 年（约 10 年后）

- [ ] **Step 4: .gitignore 追加 certs/**

在 `.gitignore` 末尾追加一行：

```
certs/
```

- [ ] **Step 5: 验证 gitignore 生效**

Run: `git status`
Expected: `certs/` 不出现在未跟踪文件列表中

- [ ] **Step 6: Commit**

```bash
git add gen-cert.sh .gitignore
git commit -m "feat: 新增自签证书生成脚本，certs/ 不入库"
```

### Task 2: nginx 配置 HTTPS + HTTP 跳转

**Files:**
- Modify: `docker/nginx.conf`（整体替换）

- [ ] **Step 1: 整体替换 docker/nginx.conf**

完整内容（80 块改跳转，新增 443 ssl 块，location 配置原样保留）：

```nginx
server {
    listen 80;
    server_name localhost;
    return 301 https://$host:8443$request_uri;
}

server {
    listen 443 ssl http2;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    ssl_certificate     /etc/nginx/certs/server.crt;
    ssl_certificate_key /etc/nginx/certs/server.key;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ws {
        proxy_pass http://go-app:8000/api/ws;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    location /api/ {
        proxy_pass http://go-app:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

- [ ] **Step 2: Commit**

```bash
git add docker/nginx.conf
git commit -m "feat: nginx 支持 HTTPS 443，HTTP 自动 301 跳转 8443"
```

### Task 3: docker-compose 暴露 8443 并挂载证书

**Files:**
- Modify: `docker-compose.yml`（nginx 服务段）

- [ ] **Step 1: 修改 nginx 服务段**

`ports` 增加 `"8443:443"`，新增 `volumes` 挂载证书：

```yaml
  nginx:
    build:
      context: .
      dockerfile: docker/Dockerfile.nginx
    container_name: ginadmin-nginx
    restart: always
    ports:
      - "8080:80"
      - "8443:443"
    volumes:
      - ./certs:/etc/nginx/certs:ro
    depends_on:
      - go-app
```

- [ ] **Step 2: Commit**

```bash
git add docker-compose.yml
git commit -m "feat: docker-compose 暴露 8443 端口并挂载证书目录"
```

### Task 4: Docker 重建并端到端验证

**Files:** 无

- [ ] **Step 1: 重建 nginx 容器**

Run: `docker compose up -d --build nginx`
Expected: 镜像构建成功、容器 `ginadmin-nginx` 启动（`docker ps` 显示 Up）

- [ ] **Step 2: 验证 HTTPS 返回 200**

Run: `curl -k -s -o /dev/null -w "%{http_code}" https://localhost:8443`
Expected: `200`

- [ ] **Step 3: 验证 HTTP 301 跳转**

Run: `curl -sI http://localhost:8080 | head -5`
Expected: `HTTP/1.1 301 Moved Permanently` 且 `Location: https://localhost:8443/`

- [ ] **Step 4: 验证 API 代理经 HTTPS 可用**

Run: `curl -k -s -o /dev/null -w "%{http_code}" -X POST https://localhost:8443/api/auth/login`
Expected: `400`（缺参数的业务错误）或 `200`（若默认 admin 密码）——只要不是 502/404 即证明 nginx→go-app 代理经 HTTPS 生效

- [ ] **Step 5: 手工回归建议（交用户验证）**

浏览器打开 `https://localhost:8443`，首次访问点"高级 → 继续访问"接受自签证书，验证：
1. 登录页渲染，`admin` 登录成功
2. 登录后 WebSocket 连接正常（浏览器控制台无 wss 报错，或页面出现实时推送功能正常）
3. 访问 `http://localhost:8080` 自动跳转到 `https://localhost:8443`
4. 抽查操作日志、数据字典等依赖 `/api/` 的页面功能正常
